## Review notes

Select an existing riding video, select a moment up to eight seconds, and confirm analysis. The source is saved locally before submission. The analysis is performed remotely. The app shows a waiting state while the server processes the job and downloads the result on a later progress check. Return to the foreground to resume checks after closing/backgrounding the app. A completed result remains retrievable for 45 minutes; the local source can be resent after expiry.

The processing server remains compatible with older installed app versions. No minimum-version increase is required for this rollout.

## App Privacy declarations completed for submission

Apple initially blocked submission because the binary requests tracking permission while the previous privacy label declared only crash data. The existing Meta integration and its bundled privacy manifests were checked against the app code and published privacy policy. All seven data types are now configured and published; the incomplete-data warning cleared before submission.

| Data type | Purposes | Linked to identity | Used for tracking |
| --- | --- | --- | --- |
| Device ID | App functionality, analytics, third-party advertising, developer advertising/marketing | Yes | Yes |
| Product interaction | Analytics, third-party advertising, developer advertising/marketing | Yes | Yes |
| Purchase history | App functionality, analytics, third-party advertising, developer advertising/marketing | Yes | Yes |
| Coarse location | Analytics, third-party advertising, developer advertising/marketing | Yes | Yes |
| Photos or videos | App functionality | No | No |
| Other data types | Analytics | No | No |
| Crash data | App functionality | No | No |

Coarse location covers IP-derived location in third-party measurement, not a newly enabled location permission. Video processing uses random job identifiers without an app account or rider profile. The declarations update store metadata; they do not change the binary's collection behavior.
