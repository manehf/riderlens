# RiderLens 1.0.5

Status: signed iOS/Android builds completed. iOS upload to App Store Connect /
TestFlight completed; Android 1.0.5 (13) is available to internal testers.
Public store review/production rollout has not been requested for this version.

Post-build Android correction: Sentry issue 7726521907 exposed that foreground
read cancellation was only wired on iOS. The Android lifecycle adapter added
after build 13 pauses health/status/result reads on background and uses the
existing deferred recovery path. This correction is not in the artifacts below;
Android needs another build/version code before public rollout. See
[the incident record](../incidents/7726521907-android-progress-recovery.md).

Post-build shared correction: result retrieval now has its own 120-second
deadline, separate from the 30-second status check, with explicit timeout
diagnostics. This change is absent from both artifacts below: Android and iOS
need new builds. The updated source passed 173 app tests and TypeScript on
September 13; real-device transfer validation remains pending. See
[result-download timeout](../incidents/7728975202-result-download-timeout.md).

## Changes

- iOS analysis submission uses a durable native background transfer, with
  foreground recovery of tasks, accepted jobs and terminal receipts.
- Analysis progress distinguishes uploading, acceptance, queue/processing and
  result retrieval. Interrupted foreground retrieval preserves the accepted job.
- Record storage/deletion and reprocessing protect against stale callbacks and
  failed persistence, while preserving existing Android and legacy worker behavior.
- Monthly-limit and paywall-flow events reach the existing GA4 delivery queue;
  purchase/restore diagnostics distinguish attempted from confirmed presentations.

No worker performance change is bundled in the app. The current production worker
already accepts the new billing event names (v44). See
[transfer validation](../ios-analysis-transfer-plan.md),
[billing measurement](../billing-analytics.md), and
[worker performance](../../worker/docs/capture-performance.md) for separate scope.

## What to test

Upload a 5 MB and a 14 MB clip, lock the phone or leave the app for more than five
minutes, then reopen and verify recovery without duplicate submissions or lost
records. Exercise offline/online recovery, deletion/reprocessing during transfer,
and completed-result playback. On both platforms, check paywall opening from
Settings and the monthly limit, sandbox purchase/restore, and GA4 event delivery.
